## Findings and material decisions

The selected file was spread across three columns. Artwork/playback lived in a
narrow right panel while the large middle panel often contained a placeholder.
Format notes preceded the preview. The collapsed connection map and separate
Used by/References disclosure trees repeated the same facts with different
navigation affordances. The selected file's identity and support were fragmented.

Use two columns: a bounded archive browser and one wide selection article. Its
reading order follows the person's tasks:

1. **What is this?** Type, filename, full archive path, selected tile/source line
   and inspection support. Inspection is explicitly distinct from runtime support.
2. **See, hear or read it.** Existing preview/playback controls first; PRG source
   first for programs. No empty placeholder between identity and useful content.
3. **How is it connected?** One visible connection view. Used by means incoming;
   References means outgoing. Each neighbor shows its first recorded evidence and
   an Inspect connection action; selecting it reveals every exact edge, source
   location, resolution explanation and available candidate navigation. More/fewer
   and existing filters bound large neighborhoods. Whole-game/multi-hop graph
   editing is not added. Tile selection still filters incoming placements.
4. **How do we know?** A plain Technical details section holds format/specification,
   decoded fields, raw board records, MIDI configuration and program reference
   evidence. Lazy decoded JSON remains one optional disclosure. Existing specific
   artwork/track/record controls remain where they preserve meaningful grouping;
   there is no new outer accordion. #137 already renamed the command reference.

Section buttons move focus/scroll without mutating URL/history or remounting media.
Shared selection/history handles every exact source/tile link and Back/Forward.
Technical records are moved as DOM nodes, retaining existing handlers. The shared
resolver, connected JSON, decoders, generic runtime and exports are unchanged.
Unsupported layouts/errors, unidentified files, missing targets, computed names,
ambiguous matches, foreign-project matches and unindexed references have distinct
plain explanations. Candidates remain evidence; inspecting one does not bind it.

## Reproducible automated evidence

Run the repository Pages workflow, including:

```
node scripts/check-asset-presentation.mjs
node scripts/check-tk3-browser.mjs site
node scripts/check-first-use-browser.mjs site dist/first-use-review
git fetch --no-tags --depth=1 origin e392e99f10754e9ad2612e76243f23753713161f
node scripts/check-selected-asset-browser.mjs site dist/selected-asset-review
```

The selected-asset check serves the staged site and the exact baseline HTML/CSS/app
with the same shared modules. It uploads two independent synthetic structures:
wrapped historical TK2 legacy records plus a three-line WAV reference probe and
unsupported-file probes; native TK3 binary records generated by the existing browser
fixture with native encounters. Exact generated ZIP bytes, SHA-256, construction,
review head, baseline, Chromium version, viewport, results and screenshots are in
the `selected-asset-review` Actions artifact. Matched screenshots use identical
TK2 inputs/selection at 1365×960 and 390×844; native board/missing/audio views
supply additional after evidence.

Both structures exercise normal archive upload, board → exact numbered tile →
incoming board use, sound → caller/source line, Back/Forward, missing/computed
references and keyboard section/source/tile focus. The same edge facts are checked
against the actual connected JSON download. Native malformed/unindexed source has
its own explanation. Unknown/unsupported files retain diagnostics/records. Mobile
checks include page overflow and exact caller navigation. Existing first-use,
real WAV/GS MIDI/animation lifecycle, source/history, JSON/PDF, title/canvas,
entry/task/movement/encounter and full staged-file production checks stay enabled.

This is **automated synthetic evidence**. No private diagnostic ZIP was supplied
or rerun. Original Toolkit execution, deployment of this PR and owner usability
acceptance are not claimed. Ambiguous/foreign-only explanatory mappings have unit
coverage; their resolver/navigation behavior remains covered by existing archive
and connection checks. Broader format/runtime limits remain in #123/#79.

## Short owner checklist

1. Open the TK2 art/audio example. Open a board, follow a numbered tile, inspect
   a Used by connection and return with Back/Forward. Check identity stays clear.
2. Open a TK3 sound and follow its calling PRG/source line. Inspect a missing or
   computed reference and confirm the explanation and raw evidence are useful.
3. Try keyboard section buttons and a narrow screen. Find decoded JSON/format
   notes, then return to preview. Confirm Play and media/export still feel intact.

Record build, archive hash, browser/device, person and observed confusion/result.
Merge, deployment, actual-ZIP execution and human acceptance remain separate states.
